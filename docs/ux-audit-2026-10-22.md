# 每日听力：主题回归与使用体验审查

审查日期：2026-10-22。基线：正式版 `f2f1e05`。目标是让“选节目 → 播放 → 回看 → 查词 → 继续听”可预测、不中断。

## 判断

现有播放器、虚拟文稿和离线架构可以继续使用。优先借鉴成熟产品的操作方式，补齐状态与反馈；当前没有更换技术栈或增加动画库的必要。下一轮应优先处理播放器导航与阅读状态，其次处理倍速、查词和跳句的操作语义，再做展开收起动效。

本次只发布根画布主题修复、基础按压反馈、减少动态效果支持和迷你播放器独立按钮。下面标为“下一轮”的项目仍是方案，并非已实现。

## 主题回归

浏览器实测：深色切到浅色后，`data-theme=light`、`color-scheme=light`、`theme-color=#FFFFFF`、`body` 为白色，但 `html` 的背景仍是 `rgba(0,0,0,0)`。上一版只验证了页面内容和 theme-color，没有覆盖根画布。这是应用自身的明确遗漏；桌面 Chromium 未复现手机原生状态栏黑条。

修复让首屏脚本与运行时同时设置不透明根画布、已解析的 color-scheme 和 theme-color，恢复前台与页面缓存时重新同步。保留 `apple-mobile-web-app-status-bar-style=default`，避免在切换主题时改变状态栏是否占据布局空间。损坏或 null 的本地设置也走系统主题初始化。

WebKit 仍有主屏幕 Web App 状态栏安全区问题记录，包含系统绘制区域在 live theme change 后不更新的报告。不能据此判定用户必然遇到同一系统问题，也不能以 DOM / CI 测试代替 iPhone 验收。发布后应在同一台设备分别验证 Safari 普通页面、主屏幕启动、后台返回、重新启动；不能以“桌面通过”宣称原生状态栏已验收。

后续补丁：为处理反向切到深色后仍保留浅色系统栏的问题，手动选择不同外观时，先保存当前音频进度和设置，等待新底色绘制后刷新一次。首帧及运行时同时声明深色 `black`、浅色 `default` 状态栏样式；按 Apple 定义，两者都在状态栏下布局，不使用改变内容覆盖范围的 `black-translucent`。启动恢复、系统主题变化、重复选择同一项不触发刷新，避免循环；存储写入失败也不刷新。刷新会暂停音频并保留进度。

## 动效约束

参考 [Apple Motion 指南](https://developer.apple.com/design/human-interface-guidelines/motion)：动作应解释状态变化，简短、可打断，并尊重减少动态效果。120ms / 180ms 是本项目的初始设计值，不是 Apple 或竞品规定的参数。

- 标签切换保持即时，不让整个页面横向飞动。
- 播放器展开 / 收起用同一轴向；必须能中途改向，不能为等动画禁用按钮。
- 文稿只在主动定位或自动跟随时平滑移动。手指滚动优先，不跟手抢滚动；远距离跳句直接定位后校准。
- 不给颜色、阴影、毛玻璃和整个文稿列表同时做大范围动画；先用 transform / opacity，录制帧时间后再定是否保留。
- 不引入全屏白闪遮罩、滚动时隐藏底栏或默认震动。

## 验收范围

本次：首屏脚本与运行时主题回归测试、迷你播放器独立按钮测试、完整单元测试 / lint / 类型 / 构建、Cloudflare 预览与正式域名资源验收。

下一轮关键场景：80 分钟节目中段暂停 → 回看 → 查词 → 收起 → 切换标签 → 重开；倍速和译文设置后不丢阅读位置；离线 / 弱网有明确状态；快速导航能被打断；减少动态效果开启时同样可操作。

性能目标应由真实设备测量：连续滚动记录长帧、关键操作记录到下一次绘制的延迟，与同设备旧版比较。现有 `/api/ui-metrics` 是汇总诊断，不能替代完整 INP、触摸手感和原生状态栏验收。
