# 节目与单词的连续操作、转场研究

日期：2026-10-22。基线：`6bb45ca`。本轮目标：减少看词的往返操作，让节目、单词详情的进入与返回具有明确的空间关系。

## 研究方式与证据范围

没有把营销截图当成交互证据。本轮结合官方交互说明、原生转场演示与实现讲解、开源产品的真实控制逻辑，以及 Apple Podcasts 网页端的实际操作。

原生 iPhone 客户端没有在本环境中运行。Apple 原生缩放的依据是 WWDC 演示与讲解；网页端实际观察只用于验证播放入口和状态连续性，不冒充原生动画实测。WWDC 视频明确把动画放慢到半速，因此不能把观看时感受到的速度直接照搬。

## 本轮落地

### 单词：从往返浏览变为连续浏览

原流程：查看 A → 返回列表 → 找 B → 打开 B。新流程：查看 A → 下一个。发音、标熟仍各自保留，不自动代替用户做选择。

- 进入时保存当前**筛选后完整列表**的快照，包括搜索结果和六级词表；不是仅保存已经显示的前 60 行。
- 本轮顺序不会被标熟、移出、到期时间更新或列表重排改变；下一词由快照中当前词的位置决定。
- 底部固定显示上一个、当前位置和下一个，边界不循环。首词禁用上一个，末词提供返回列表。
- 切词使用浏览器历史替换；看过很多词，点一次返回仍回原列表。列表原来的搜索、展开条数和滚动位置继续保留。
- 会话内刷新保留队列；最多保留四轮。存储写入失败时当前轮仍在内存中可用。过期或外部直达链接不伪造一轮单词。
- 切词、返回、进入原节目时停止旧词的例句和语音；旧请求不能把 A 的例句写到 B 下方。例句网络错误与“没有例句”分开，可重试。
- 只预热下一词的例句索引，不下载整轮音频；当前词仍只预取最前面的两条例句音频。

### 动效：围绕来源、方向和操作速度

| 动作 | 行为 | 本项目选定节奏 |
| --- | --- | --- |
| 点节目行、迷你播放器、单词行 | 来源区域展开至详情；内容短暂淡入 | 几何过渡 320 ms，渐慢曲线；内容约 280 ms |
| 返回 | 详情缩回正确来源；来源不在屏幕内时收缩淡出 | 约 260–320 ms，不强制改变滚动位置 |
| 下一个 / 上一个词 | 只切换阅读区，向前/向后使用相反的小幅横向运动 | 180–200 ms，位移 12–18 px；控制区保持原位 |
| 按住按钮、节目行、单词行 | 轻微缩小，松开恢复，然后进入详情 | 120 ms，避免只降低到很暗的透明度 |
| 快速连续操作 | 中断旧动画，只有最新页面可以提交；不排队播放旧导航 | 不额外等待动画结束 |
| 减少动态效果、浏览器原生返回手势、旧浏览器 | 减少动态效果/原生手势直接更新；无 View Transitions API 时使用短暂的进入/返回提示 | 不阻塞操作、不重复叠加原生手势动画 |

这些时长是本项目的设计选择，不是 Apple Podcasts 的实测参数。没有增加动画依赖，也没有让音频时钟、字幕滚动参与每帧 React 页面重绘。

View Transitions 的旧、新快照必须使用唯一名称；隐藏页、重复节目条目分别处理。特别处理了一个 API 陷阱：`skipTransition()` **不会取消更新回调**，因此增加版本保护，防止较早的导航在快速操作时晚到并覆盖新页面。页面返回只使用本应用拥有的历史记录，外部直达详情的返回不会意外离站。

## 验证与仍有边界的部分

自动化覆盖：标熟后仍按原队列继续、越过分页边界、首尾、往返历史深度、返回后的搜索和滚动、旧例句请求、错误重试、转场被中断、当前项目返回来源、来源离屏、减少动态效果和无 API 降级。预览站还需实际操作节目/词表进入返回、连续看词、播放及主题，检查控制台与布局。

本轮没有声称完成原生手指跟随、拖拽关闭和弹簧速度继承，也没有声称在实体 iPhone 或低端设备上测得帧率。这类体验仍需实际设备验证。节目内的字幕逐句跟随、播放队列和复习评分也各有独立语义，不通过把所有页面统一套上一个慢动画来解决。
